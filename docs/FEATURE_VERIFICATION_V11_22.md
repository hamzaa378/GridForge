# GridForge v11.22 Feature Matrix

| Area | Implementation | Evidence and limits |
|---|---|---|
| Manual group editor | One group per line; item labels split by `|`; escape `=`, `|`, or `\` with `\`, and write `\\` for one literal backslash; prefix edge spaces with `\`; `(blank)` selects empty source cells. Duplicate assignments, missing items, empty labels, and conflicting date/numeric group settings are rejected. Distinct item-value options are cached by source and grouping definition, invalidated after edits, paste, sort, query refresh, undo/redo, or workbook/source changes; sorting refreshes summaries, and manual group mappings are indexed once per filter refresh. | TypeScript check/build. No UI test. |
| Pivot Summary calculation | Mapped item captions participate in nested row/column aggregation and ordinary Pivot Summary filters. Unlisted categories retain their source captions. Legacy single-field report filters continue to validate after migration to the filter-list representation; report filter text matching is case-insensitive. Cross-sheet formula invalidations expose affected cells so dependent source ranges refresh through a serialized queue. | Focused Node code checks and TypeScript check/build. |
| Pivot Summary calculation responsiveness | Create/update, single-report refresh, workbook-wide Refresh All, source-edit refresh, slicer filtering/connections, row/column group toggles, collapse/expand-all, and source-detail extraction calculate from serialized workbook snapshots in module workers. Refresh All processes up to four summaries per snapshot, applying each to the worker copy before calculating dependent summaries; if a result is rejected, later jobs are recalculated from the live state. Edit, undo/redo, paste, import, and query refresh requests are debounced and serialized; stale workbook or saved PivotTable-definition results are discarded and queued again. | Sequential dependent-summary worker regression, focused Node checks, and TypeScript check/build. Slicer and group changes preserve rollback behavior after worker results are validated. |
| Pivot source capacity | Source ranges can use the supported worksheet limit of 1,000 rows × 104 columns (104,000 cells); the former 12,000-cell restriction was removed. | Worker-job regression check on a 13,000-cell source; no UI test. |
| Specialized chart interchange | Waterfall, Pareto, Box-and-whisker, Funnel, Treemap, and Sunburst serialize as native Excel ChartEx and import back as editable GridForge charts. Histogram remains a standard column-chart fallback. | Code-only XLSX export/import round-trip for all six ChartEx types; no Excel GUI check. |
| Top/Bottom value filters with empty-item visibility | “Show items with no data” no longer restores labels excluded by a Top/Bottom value filter, including grouped paths under nested axes. | Focused regression check for Top N plus empty-item visibility; TypeScript check/build. |
| GETPIVOTDATA | Grouped field captions are recognized as field criteria, and row calculations resolve source items to configured group captions. | TypeScript check/build only. No formula runtime tests. |
| XLSX export | Adds a grouped cache field using `fieldGroup`, `discretePr`, `groupItems`, and one base-item mapping per source cache item. Cache records point at generated group items. Caption filter items are emitted as hidden/visible cache items without a runtime initialization error. | Focused Node PivotTable export checks; no Excel GUI validation. |
| PivotChart XLSX linkage | Supported GridForge charts linked to Pivot Summaries export native `pivotSource` and PivotTable `chartFormats` metadata. Import code reconnects charts by the native PivotTable name when present. Excel field-button behavior has not been verified. | Code-only export metadata check and importer code inspection; no Excel GUI validation. |
| XLSX import | Reads discrete group mappings from supported local-source PivotTables, resolves worksheet table-name and local defined-name sources, and restores group membership into the Pivot Summary definition. | Code inspection and build only; unsupported/malformed group structures are rejected. |
| PivotTable import/export round-trips | Single new-style multi-select report filters no longer acquire an incomplete legacy alias that breaks the second validation during refresh. Native export imports back with its report selection and can refresh after source edits. Top N filters survive with empty-item visibility enabled. Manual groups restore their explicit groups while pass-through singleton cache groups remain ungrouped. | Node code-only XLSX export/import/refresh round-trips using `@xmldom/xmldom`; no Excel GUI validation. |
| Pivot slicer validation | Saved/imported slicers are rejected if connected to a date, numeric, or manually grouped field, matching the editor's ungrouped-field rule. Ordinary ungrouped slicer fields remain accepted. | Focused Node code-only validation check; no live UI test. |
| Pivot date serial handling | Date filters and date grouping map the Excel 1900 system correctly around serial 60, including the fictitious 1900-02-29 day. The date-range editor uses the same shared conversion helpers. | Focused Node serial-boundary checks and TypeScript check/build; no live UI or Excel check. |
| Remaining PivotTable gaps | Native PivotCharts and slicer/timeline parts, multilevel date grouping, calculated fields/items, Data Model and OLAP behavior, full Excel refresh/cache compatibility, and broader Excel acceptance remain incomplete. | See [compatibility audit](EXCEL_COMPATIBILITY_AUDIT.md). |

## Verification

Validation included all 1,003 Node code tests, `npm run check`, `npm run build`, and Windows installer compilation with its test phases skipped. The installer hash and size match the release manifest. Windows runtime tests, live UI checks, installer launch, and Excel GUI validation were not run.
