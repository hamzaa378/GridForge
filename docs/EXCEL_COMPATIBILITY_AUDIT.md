## Executive assessment

**GridForge is a local, browser-based, Excel-inspired spreadsheet editor, not a complete Microsoft Excel replacement.** It has 507 registered Excel-style function names, including a workbook-context implementation of `GETPIVOTDATA` for supported generated summaries, independently implemented formula parsing, XLSX/XLSM interoperability and spreadsheet interactions. Function registration alone does not establish Excel behavior equivalence.

There are **two distinct levels of evidence**:

1. **GridForge-only verification:** The 506-name offline probe set has deterministic current-source probes. The additional workbook-context `GETPIVOTDATA` function requires a saved generated Pivot Summary and is not covered by that older per-function fixture. A probe is not a full behavioral test.
2. **Saved Microsoft Excel differential evidence:** A complete Excel 16.0 (build 20430.0) run exists for the same fixture hash. Recomparison with current GridForge outputs gives 450/456 matching comparable cases (98.68%), 2 differences and 4 known semantic differences. Excel-rejected names, assignment failures, online functions and volatile functions are separately reported. This one-case-per-name result does not mean that all functions are on par with Excel.

## Confirmed defects repaired during the audit

1. **Negative half rounding:** `ROUND(-1.5,0)` previously returned `-1`, but Excel returns `-2`. Core rounding now uses symmetric, away-from-zero tie behavior.
2. **Typed literal coercion in aggregations:** `SUM("3",4)` previously returned `4`, and `SUM(TRUE,2)` returned `2`. The parser evaluator now distinguishes directly typed literal values from referenced cells for `SUM`, `COUNT`, `AVERAGE`, `PRODUCT`, `MIN` and `MAX`.
3. **COUNTIF and related criteria wildcards:** `COUNTIF(range,"A*")` previously returned zero for `Apple` and `Apricot`. Criteria matching now supports Excel-style `*` and `?`, with `~` escaping, for text equality/inequality matching.

Each repair is exercised through the public formula evaluator in the regression suite. Additional edge cases may remain.

## Known behavior gaps relative to Excel

- **Dynamic spilling:** A bounded set of array-producing formulas can spill into adjacent cells, return `#SPILL!` on collisions, and use basic spill references. XLOOKUP now returns aligned rectangular row/column arrays to this spill engine. Full Excel dynamic-array semantics, persistence, compatibility and complete function coverage remain incomplete.
- **Excel date model:** Date serials use a simplified 1900-based convention. Import normalizes date-formatted numeric literals from 1904-system workbooks by 1,462 days; formulas and non-date-formatted numerics are not shifted. Supported Excel date number formats survive XLSX round-trips and a bounded set of date/time tokens render in the grid; unsupported tokens remain preserved but display numerically. The 1900 leap-year anomaly, custom format detection, locale parsing and timezone cases have not been exhaustively compared. `TIMEVALUE` accepts AM/PM text in addition to 24-hour input; `DATEVALUE` accepts year-first numeric or English month-name forms and rejects ambiguous locale-numeric text. Locale/date parity remains incomplete.
- **Full-function fidelity:** 507 local or workbook-context registered names do not imply 507 identical implementations. Nine other names require external services. The older 506-name one-case comparison has two measured differences and four known semantic differences; 36 functions were unavailable/rejected by that Excel build, six Excel formula assignments failed, three online cases were skipped, and five volatile cases were excluded. `GETPIVOTDATA` only supports generated summaries, base aggregations and supported filters; `FORECAST.ETS` is a simplified trend estimate; `TRANSLATE`, `IMAGE`, `LAMBDA`, `LET`, `GROUPBY`, higher-order functions and specialized financial functions have restricted semantics.
- **Grid size:** The default worksheet has 400 rows × 52 columns (20,800 cells). Excel supports much larger worksheets.
- **Cell presentation and printing:** Not every Excel format, conditional-format rule, validation rule, chart, pivot table or workbook-level feature is preserved. Supported single-cell HTTP/HTTPS/mailto and internal-location hyperlinks survive XLSX import/export and display as clickable links in GridForge; links in formulas and named destinations have narrower activation support. Custom number-format codes survive XLSX import/export, but only a subset is rendered. Basic page orientation, paper size, fit-to-page, margins, print area, gridlines, headings and repeating print titles are saved to XLSX. Repeated title rows are also rendered in the browser print view; repeated columns are preserved for Excel but not reproduced in browser print. Page breaks, headers/footers, print ordering and Excel's full print preview are not implemented.
- **Cross-sheet references and workbook links:** Basic same-workbook cell and rectangular-range references are supported, including quoted sheet names and direct-reference repair after rename/delete. Reference-oriented functions, workbook-scoped names, external links and arbitrary Excel object-model compatibility remain incomplete.
- **Chart fidelity:** Standard chart types and stock HLC/OHLC charts have native editable XLSX output. Histogram now uses native ChartEx binning with editable source formula, bin count or width, and supported import; specialized charts retain titles, data-label visibility and configured single-series color. Standard charts support data-label positions and mixed column/line combo import/export; series names linked to matching worksheet headers export as cell references. Waterfall supports multiple user-selected total/subtotal points in preview and ChartEx export/import. Other specialized types use native ChartEx layouts with one numeric series and a local category range. Multi-level Treemap/Sunburst category columns now export as separate ChartEx levels; hierarchy-specific metadata, ChartEx label positions and advanced style settings still do not fully round-trip or have Excel UI acceptance evidence.
- **Lookup formula behavior:** `MATCH`, `XMATCH`, `XLOOKUP`, `VLOOKUP`, `HLOOKUP`, and `LOOKUP` now cover supported exact/approximate and wildcard modes. Sorted approximate lookup functions validate key ordering; XMATCH/XLOOKUP include forward/reverse and binary search options. `TEXTBEFORE`, `TEXTAFTER`, and `TEXTSPLIT` support more Excel-style optional arguments. Broader Excel comparisons for type coercion, wildcard details, locale behavior and boundary cases remain outstanding.
- **Power Query and data analysis:** GridForge supports GridForge-specific worksheet pipelines and public HTTPS CSV/JSON refresh, with 3 MB response limits and server CORS requirements. Native Power Query M, query folding, database connectors, credentials, incremental refresh and native XLSX query mashups are unsupported. GridForge exports/re-imports a bounded native PivotTable subset with per-field Show items with no data visibility for observed row/column paths under report filters. It supports nested row and column fields bounded by source width and output space with editable Rows, Columns, and Values field order, value calculations bounded by available worksheet columns, including repeated source fields, fields shared between a row or column axis and Values, and custom value captions; imported Values-only PivotTables are supported. Aggregations include independent Sum, Count, Count Numbers, Average, Minimum, Maximum, Product, StdDev, StdDevp, Var or VarP aggregation; Count includes formula cells that evaluate to an empty string, while Count Numbers includes only numeric results, and new calculations use numeric/text-aware defaults; Show Values As percentages of grand, row, column, parent-row or parent-column totals plus % Of a Previous, Next, or specific item, Running Total In, % Running Total In, Difference From a Previous, Next, or specific item, % Difference From, and rank ascending/descending using a selected row/column Base field, plus Index calculated from its row, column and grand totals; configurable tabular, outline, or compact report layout, per-field row and column sorting, row subtotals above or below groups with optional blank lines between parent groups, row/column subtotals and row/column grand totals; row/column item filters and caption filters (including inclusive Between/Not between); and multi-item report filters bounded by source-field count. Multi-level date hierarchies, calculated fields/items, native Excel timelines, full PivotChart field-panel interactivity, Data Model, Power Pivot, DAX and OLAP remain unsupported; GridForge emits native PivotChart source and chart-format metadata for supported worksheet-linked charts, without live Excel acceptance verification. GridForge provides slicer cards that connect and reconfigure compatible summaries on a worksheet when they share a source range and an ungrouped row/column field. Selection and connection changes refresh transactionally; saved field filters are restored on disconnect or deletion. Slicer item lists are cached until source values change. XLSX import/export now writes native Excel slicer cache, slicer view, worksheet relationship and drawing parts, including selected items and geometry; compatible PivotTables sharing the same source and grouping share a native PivotCache and can be connected by the exported slicer. If connected GridForge PivotTables need different native caches, the exported slicer connects only to the primary PivotTable's cache. This is code-checked only; there is no live Excel acceptance evidence. The UI regenerates the report as worksheet cells rather than providing the full Excel interactive field panel and native pivot cache editing experience. Nested row and column groups can be expanded/collapsed in the GridForge sheet with saved per-group state; XLSX export emits the native per-item hide-details flag and supported imports restore matching group paths. Since OOXML stores hide-details on the field item, identical labels in different parent groups cannot be represented independently and may all reopen collapsed. Double-clicking a generated value, subtotal or grand total, or choosing Show PivotTable details from its context menu, creates a Details worksheet with the matching filtered source records and copies source styles and custom dimensions; the detail count is bounded by the 1,000-row worksheet limit. GridForge charts linked to Pivot Summary output follow range changes; XLSX export adds native PivotChart source and PivotTable chart-format metadata for supported DrawingML charts. The in-app chart editor remains GridForge-specific, and Excel PivotChart field-button behavior is not yet verified. GridForge limits each generated summary to 250,000 output cells to avoid unresponsive bulk updates. Direct edits, recalculated local source formulas, and cross-sheet formula invalidations refresh affected summaries through serialized source-range updates; PivotTables based on a formatted table extend their source range when table rows are appended. Refreshing queries also refreshes dependent summaries. Complex Excel PivotTables that use unsupported features, or whose local source cannot be resolved, are skipped with an import warning; local PivotTables sourced from another worksheet are supported.
- **Remaining high-impact work, in practical order:** (1) Power Query M, Data Model, DAX, OLAP and Excel connector/credential refresh; (2) richer PivotTables with multi-level date hierarchies, native Excel timelines, complete slicer connections across differing cache definitions, and verified PivotChart field-panel interactivity (GridForge exports native PivotChart links for supported standard charts, but has no live Excel acceptance evidence); (3) advanced specialized-chart semantics and complex chart import, especially hierarchy, histogram customization beyond a single numeric series, Waterfall/ChartEx limitations and full chart styling; (4) broader formula-by-formula Excel differential comparisons, locale/date/error/precision fidelity and complete dynamic arrays; (5) larger worksheets and memory/performance work; (6) protection, threaded comments, coauthoring, nested or named-destination hyperlinks, 3D sheet references and richer workbook objects; (7) full page breaks, headers/footers, print order and print preview.
- **Pivot item-selection and manual order:** An omitted item filter means all items; a present filter with an empty value list means no visible items. Summary refresh, XLSX PivotField export, slicer selection, and slicer connection updates preserve this distinction. For imported manually sorted fields, cached member order is preserved during summary refresh and XLSX export. The GridForge dialog supports per-field manual reordering with Move Up/Move Down controls; omitted items follow source encounter order. This behavior is code-checked, not validated in a live Excel session.
- **Pivot date cache boundary handling:** Native date-group export derives OOXML date bounds through the same 1900-system serial conversion used for Pivot Summary labels. Excel's fictitious serial 60 (1900-02-29) remains represented in the cache records, but is omitted from explicit ISO date bounds because it is not a valid calendar date; automatic cache bounds remain enabled. This is code-checked and built, not validated in a live Excel session.
- **Pivot field capacity:** The former eight-field cap is removed for Rows, Columns, report filters, item/caption/date filters, field grouping, sorting, and value calculations. These selections are now bounded by source-field count, destination worksheet columns, and the existing output-cell/worksheet limits; XLSX import uses the same worksheet-aware cap. Saved percentage-format metadata follows the physical worksheet capacity instead of the old 20,800-cell default-sheet bound. Formula and UI checks/builds passed, but no broad high-field-count behavior has been validated in Excel.
- **VBA:** VBA does not execute in the browser. On Windows, the optional Excel bridge can explicitly ask installed desktop Excel to run a trusted macro. This does not constitute an in-browser VBA runtime.
- **XLSM:** Supported cell edits are merged into the original macro-enabled package. Structural edits, advanced formula structures, signatures and unsupported package parts are not guaranteed.
- **Localization and volatility:** Locale-specific separators, coercions, dates, 15-digit precision, and time-dependent functions require targeted desktop-Excel comparison.

## Suggested positioning for reviewers

> GridForge is a **local, browser-based spreadsheet application with an Excel-familiar interface**. It implements a custom TypeScript formula engine with 507 registered Excel-style functions, including a workbook-context GETPIVOTDATA implementation for supported generated summaries, supports selected XLSX/XLSM workflows, and provides optional desktop Excel integration for VBA. Compatibility with Microsoft Excel is being validated with a reproducible cross-engine test suite; it is not a drop-in replacement.

Do not call it "Microsoft Excel for the browser", claim that all 507 functions are Excel-identical, or publish an Excel compatibility percentage based only on static expected values.
