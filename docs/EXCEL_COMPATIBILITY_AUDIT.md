## Confirmed defects repaired during the audit

1. **Negative half rounding:** `ROUND(-1.5,0)` previously returned `-1`, but Excel returns `-2`. Core rounding now uses symmetric, away-from-zero tie behavior.
2. **Typed literal coercion in aggregations:** `SUM("3",4)` previously returned `4`, and `SUM(TRUE,2)` returned `2`. The parser evaluator now distinguishes directly typed literal values from referenced cells for `SUM`, `COUNT`, `AVERAGE`, `PRODUCT`, `MIN` and `MAX`.
3. **COUNTIF and related criteria wildcards:** `COUNTIF(range,"A*")` previously returned zero for `Apple` and `Apricot`. Criteria matching now supports Excel-style `*` and `?`, with `~` escaping, for text equality/inequality matching.

Each repair is exercised through the public formula evaluator in the regression suite. Additional edge cases may remain.

## Known behavior gaps relative to Excel

- **Dynamic spilling:** A bounded set of array-producing formulas can spill into adjacent cells, return `#SPILL!` on collisions, and use basic spill references. XLOOKUP now returns aligned rectangular row/column arrays to this spill engine. Explicit `@` implicit intersection returns the formula-position value for direct range references and the top-left item for computed arrays. Full Excel dynamic-array semantics, persistence, compatibility and complete function coverage remain incomplete.
- **Excel date model:** Date serials use a simplified 1900-based convention. Import normalizes date-formatted numeric literals and numeric bounds on date validations from 1904-system workbooks by 1,462 days; formulas and non-date-formatted numerics are not shifted. Supported Excel date number formats survive XLSX round-trips and a bounded set of date/time tokens render in the grid; unsupported tokens remain preserved but display numerically. The 1900 leap-year anomaly, custom format detection, locale parsing and timezone cases have not been exhaustively compared. Date Validation and Pivot date conversion now share a 1900-system converter that preserves serial 60; date-validation inputs use ISO text for this otherwise unrepresentable calendar date, restore saved bounds after switching field modes, and reject invalid ISO dates. `TIMEVALUE` accepts AM/PM text in addition to 24-hour input. `DATEVALUE` uses the current runtime locale for numeric order and month names; an independent workbook locale, all date aliases, date-system and timezone edge cases remain incomplete.
