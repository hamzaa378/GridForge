# GridForge 12 Desktop for Windows

GridForge Desktop packages the GridForge spreadsheet application as a Windows program. It includes an Excel-inspired ribbon, formula engine, charts, PivotTables, workbook tools, and XLSX/XLSM support. Excel compatibility is broad but incomplete; see the compatibility audit for known limits.

## What the user installs

- **GridForge-Setup-<version>-win64.exe**: ordinary Windows installer with Start menu shortcut, optional desktop shortcut, and uninstall entry
- **GridForge-Portable-win64.zip**: alternative standalone folder for non-installer use. Extract **the entire folder**, then run `GridForge.exe`
- **GridForgeExcelBridge.exe**: separately run optional bridge for **trusted VBA macros only**. Excel desktop must be installed and able to run the macro under its Trust Center settings.

Neither package requires end users to install Node.js, npm, Python or pip packages. **Microsoft Edge WebView2 Runtime** is required on Windows (commonly present on Windows 11). If missing, install Microsoft's official runtime; it is not bundled in this release.

## Install and run

1. Use Windows 10 or 11, 64-bit, with Microsoft Edge WebView2 Runtime installed.
2. Open the versioned `GridForge-Setup-<version>-win64.exe` installer and follow the prompts.
3. Choose whether to create a desktop shortcut.
4. Launch **GridForge** from the Start menu.
5. Open a supported `.xlsx`, `.xlsm`, `.ods`, `.csv` or GridForge `.json` using the **File > Open** command (`Ctrl+O`).
6. Save to disk with **Ctrl+S** for XLSX, or use File menu exports. The desktop app opens a **native Windows Save As dialog**.

The app starts a loopback-only local server internally on an available port at `127.0.0.1`. This is normal and does **not** mean it needs Internet access. Each launch picks its own port, so simultaneous or stale instances do not contend for one fixed port.

## Autosave and data retention

Edits are stored in the Windows embedded browser profile at `%LOCALAPPDATA%\GridForge\WebView2`, with a stable local origin. The profile is **different from GridForge opened in Chrome/Edge**; existing browser-local workbooks will not automatically migrate. Export them from the browser version to `.json` or `.xlsx`, then open in the desktop version.

Always export important workbooks to files: embedded browser storage is not a replacement for explicit backups. The uninstaller intentionally leaves the profile and workbooks on disk. To erase it manually, back up important files, close GridForge, then remove `%LOCALAPPDATA%\GridForge`.

## Defined names

Use **Formulas > Define Name** to create a name for the active worksheet or the entire workbook. Names can refer to a cell or range, or use a supported formula such as `=SUM(Sheet1!A1:A10)` or a `LAMBDA`. Worksheet-scoped names take precedence over workbook-scoped names with the same spelling. The Name Manager displays comments and hidden-name metadata. References inside both scopes update when worksheets are renamed, and become `#REF!` if the referenced sheet is deleted. Excel's complete defined-name semantics and external workbook links are not supported.

## Worksheet capacity

GridForge keeps worksheets sparse and supports a canvas up to 250,000 rows by 2,048 columns. The default blank canvas is smaller (400 rows by 52 columns). Each worksheet is capped at 2,000,000 populated or formatted cells, XLSX import at 1,500,000 cell records per sheet, and clipboard actions at 50,000 cells per operation. Clearing selected content or formatting uses sparse entries to avoid creating work for every blank cell. Some tools have lower limits. XLSX file and worksheet XML size limits still apply; GridForge does not match Excel's maximum worksheet size.

## Important compatibility notes

GridForge has **506 locally evaluated or workbook-aware registered formulas** plus **10 connected-function names** that require services and are not fully operational offline. `AREAS` validates one cell or range reference and counts it; union references are not supported. `REGEXEXTRACT` supports first-match, all-match, and capture-group modes with bounded regex input and patterns. Dynamic arrays spill from supported formula results; unary and binary operators work element-wise on matching bounded array shapes. The per-formula output limit is 20,000 cells, and some Excel array error/shape semantics differ. Export options include XLSX/XLSM, ODS, CSV, TSV, GridForge JSON, printable HTML for the active worksheet, and the system print dialog (including PDF printers). CSV/TSV/ODS exports contain calculated values. ODS translates the supported formula subset, preserves supported cell formatting, print settings, validation, safe hyperlinks and AutoFilters, and exports native charts for common types. Unsupported formula text and GridForge worksheet objects can be restored by GridForge from private ODS metadata; other ODF applications do not calculate those formulas or recognize those objects. Specialized charts include a rendered preview; GridForge chart settings round-trip, while external ODF chart import is limited to common types with contiguous source ranges. Macros and unrelated embedded objects are not preserved. JSON preserves GridForge workbook structure. The tested Excel parity does not establish full Excel equivalence. XLSM preserves VBA where supported; VBA **does not execute inside GridForge itself**.

To use Excel VBA: start the separate `GridForgeExcelBridge.exe`, copy its random token to the GridForge **Automate** panel, select an existing trusted VBA procedure and explicitly approve execution. This requires Microsoft Excel desktop and is not automatic. Never run untrusted macros.

## Troubleshooting

- Blank window or WebView error: confirm Microsoft Edge WebView2 Runtime is installed and current. Restart GridForge.
- Failed startup: confirm Microsoft Edge WebView2 Runtime is installed, then restart GridForge. The app chooses a free local port automatically.
- Old browser workbook not showing: this is a separate desktop profile. Export from the browser copy and import to desktop.
- SmartScreen shows an unknown publisher: the example release is **unsigned**. For public distribution, sign the installer and executables with a trusted code-signing certificate. Don't tell users to bypass organizational policies.
- Macros unavailable: install desktop Excel and use the separately launched, user-approved Excel VBA bridge. WebView2 alone does not execute VBA.
- Incorrect formulas or unsupported Excel workbook features: refer to the bundled compatibility documentation; report a minimal reproduction.

## Uninstall

Windows Settings > Apps > Installed apps > GridForge > Uninstall, or use **Uninstall GridForge** in the Start menu. Workbook data in `%LOCALAPPDATA%\GridForge` remains unless manually removed.

## Macro Studio (offline)

Open **Start → GridForge → GridForge Macro Studio** or choose Automate in the main GridForge window. Import a `.json` macro, enter any parameter overrides, click Preview, then Run. This executes the GridForge v4 declarative action engine, not Microsoft VBA, and needs no Excel installation. See `MACRO_STUDIO_V4.md`.

## v10.7 charts and visual formatting
Select data on a worksheet, open **Insert**, and select Column, Bar, Line, Area, Pie, or Scatter. Edit the title/source in the preview dialog, then drag the chart header to move it or its bottom-right corner to resize. Charts can be downloaded as SVG or high-resolution 2x PNG images. Supported chart types export as editable native Excel chart objects; specialized ChartEx layouts include Histogram, Waterfall, Pareto, Box & Whisker, Funnel, Treemap, and Sunburst. Box & Whisker charts offer inclusive/exclusive quartiles, inner/outlier points, and mean markers/lines. **Chart Design > Quick Layout** applies common label, minimal, legend-focus, data-table, and axis-title arrangements. The same ribbon has controls for pie/doughnut leader lines and supported legend keys in labels. **Format > Reverse values** reverses the value direction for supported chart types, and scatter charts also offer a horizontal value-axis toggle. For supported category charts, **Chart Design > Data Table** shows source values below the plot; **Table Keys** adds each series color and name. The SVG preview abbreviates very large tables, while XLSX export writes the native chart data-table option. **Plot Hidden Data** restores filtered and manually hidden worksheet rows or columns to supported standard charts; it round-trips through Excel chart settings. For scatter charts with several independent domains, select **Each scatter series has its own X/Y column pair** and arrange the source as `X1, Y1, X2, Y2, …`; an optional leading label column is allowed; numeric point IDs are recognized when the header names the column **ID**, **Point ID**, **Sample ID**, or similar. The chart editor also exposes scatter horizontal and vertical axis bounds and major units. Combo charts can mix column, line, and area series and use a secondary logarithmic value axis with bases 2–1000 in XLSX; ODS stores the supported base-10 form. The right-hand value axis can also be reversed independently. Line, scatter, and combo-line series also offer a per-series **Smooth line** setting, previewed in SVG and stored in XLSX/ODS chart metadata. The chart gallery also includes **Stacked area** and **100% stacked area** charts. Advanced chart import and editing are still partial. XLSX charts with cross-sheet, external, disconnected, or plot groups outside the supported column, line, and area combinations are skipped with a warning instead of being silently rebound or reduced to one plotted layer; see the compatibility audit. Use **Accessibility description** in the chart editor to add concise alt text for screen readers; it is kept in GridForge workbooks and supported Excel chart drawing metadata. The Home tab offers font, size, color, cell borders, wrap text, strikethrough, and cell-style presets.

## Refreshable queries and Pivot date filters

Choose **Data → New Query** to save a repeatable worksheet cleanup or public HTTPS CSV/JSON refresh. Worksheet queries can append up to seven additional ranges: enter comma- or semicolon-separated ranges, give each source a header row, and keep the header names in the same order. Duplicate header rows are removed before the selected transformations run. Combined source data is limited to 12,000 cells. A separate bounded M subset is now described below; authenticated connectors, full M, query folding and an Excel Data Model are not included.

In **Pivot Summary**, select an ungrouped date field and use **This month**, **This quarter**, or **This year** to fill the inclusive date range. These presets filter the GridForge Pivot Summary; they do not create a native Excel Timeline object.

### Power Query M subset

Recent bounded M additions include `Table.ReplaceRows` for replacing an in-range slice with scalar rows or complete records. An empty replacement removes rows, while a zero-length replaced range inserts rows. The engine validates widths, scalar values, row/cell caps, and range boundaries. Numeric helpers also include `Number.Factorial`, `Number.Combinations`, and `Number.Permutations`; they require non-negative whole-number arguments, cap factorial at 170 and iterative combination/permutation work at 12,000 steps, and use binary floating-point rather than arbitrary-precision integers.

`Number.IsEven` and `Number.IsOdd` classify finite numeric values by remainder parity, including negative values and fractional values (which are not odd/even integers); null propagates. Their input must otherwise be a finite number.

The bounded trigonometric M helpers now include `Number.Sin`, `Cos`, `Tan`, `Asin`, `Acos`, `Atan`, `Atan2`, `Sinh`, `Cosh`, and `Tanh`. They accept finite numeric arguments, preserve null, reject inverse sine/cosine inputs outside [-1, 1], and fail clearly if a result overflows. This still uses binary floating-point and does not implement M's decimal-number precision options.

The bounded M byte/bitwise family now includes `Number.BitwiseAnd`, `Number.BitwiseOr`, `Number.BitwiseXor`, `Number.BitwiseNot`, `Number.BitwiseShiftLeft`, and `Number.BitwiseShiftRight`. Operands must be safe integers; shifts are limited to 0–52 bits and any result outside JavaScript's safe-integer range is rejected. Null propagates. These implementation bounds are stricter than M's underlying numeric range.

The expression engine recognizes `Number.E`, `Number.Epsilon`, `Number.PI`, `Number.NaN`, `Number.NegativeInfinity`, and `Number.PositiveInfinity`. `Number.IsNaN` distinguishes NaN from infinities. Special values are usable in expressions but cannot be loaded into worksheet cells; query tables continue to require finite scalar numbers. Division-by-zero and broader IEEE-754 propagation are not implemented across general M arithmetic.

`Number.FromText` converts invariant decimal strings, including decimal and exponent notation, while rejecting grouping separators or non-empty culture arguments instead of silently guessing locale; an empty culture string explicitly selects invariant parsing. `Number.FromText(null)` returns null.

`Number.ToText` supports null, finite numeric values, NaN, and infinities in invariant general text form. Format-string and culture overrides are rejected explicitly; custom numeric formats are not yet implemented.

Date hierarchy helpers now include `Date.MonthName`, `Date.DayOfWeekName`, `Date.WeekOfMonth`, and `Date.IsLeapYear`. Month/day names are English-only (empty culture, `en`, `en-US`, and other `en-*` tags); other culture requests error instead of silently returning English. `Date.WeekOfMonth` accepts a `Day.*` first-day selection and defaults to Sunday in this subset.

The M `#date(year, month, day)` constructor now validates Gregorian calendar parts and returns the workbook's 1900-system serial so it can feed the bounded date functions. Results remain worksheet scalar values rather than native M typed date objects.

Calendar-list construction adds `#duration(days, hours, minutes, seconds)` and `List.Dates(start, count, step)`. The duration is represented internally as fractional days; date generation is capped at 12,000 results and at the worksheet's supported serial range. `List.Dates` requires a `#duration` step and does not yet support the complete M date/time typed-value model.

`Duration.From` preserves an existing duration and accepts a finite day fraction or strict duration text, and `Duration.FromText` parses the bounded `[-]d.hh:mm:ss[.fraction]` / `[-]hh:mm[:ss[.fraction]]` shapes. `Duration.ToRecord` and `Duration.Days/Hours/Minutes/Seconds` return sign-aware normalized components; seconds are rounded to 100-nanosecond steps on extraction. `Duration.TotalDays/Hours/Minutes/Seconds` return checked totals and preserve `null`. Locale/culture parsing remains unsupported, and underlying values use binary floating-point days rather than native M duration ticks.

`Duration.ToText` emits normalized `day.hh:mm:ss` text, with fractional seconds when present. The optional format argument is rejected when non-null, matching the documented deprecated-argument behavior.

Duration values support bounded addition/subtraction with other durations, unary negation, numeric multiplication/division, and ordering comparisons. Adding or subtracting a duration from a number treats that number as a GridForge worksheet date serial and enforces the worksheet range; subtracting a serial from a duration is rejected. Full M date/time type checking and exact tick arithmetic remain incomplete.

`#datetime(year, month, day, hour, minute, second)` validates Gregorian date and clock components, then encodes the value as a worksheet 1900-system serial with a fractional day. `DateTime.ToRecord` exposes Year, Month, Day, Hour, Minute and Second fields. These helpers support bounded calendar-table construction; they do not preserve native M datetime types or time zones, and fractional seconds inherit worksheet floating-point precision. They are useful for constructing or inspecting local worksheet timestamps, not for timezone-aware data.

`DateTime.FromText` parses only the exact local ISO shape `YYYY-MM-DDTHH:mm:ss` with optional fractional seconds (up to nine input digits). It rejects timezone suffixes, spaces in place of `T`, and locale-formatted dates instead of guessing. Its result is a worksheet serial with a fractional day; subsequent calculation precision remains binary floating point.

`DateTime.From` accepts a bounded GridForge worksheet serial or an exact ISO local date/timestamp, preserves `null`, and rejects non-empty culture overrides. Numeric inputs follow GridForge's worksheet 1900 date system; this differs from the full M `DateTime.From` numeric/OLE Automation convention. Text inputs remain strict and timezone-free.

`Date.From` accepts worksheet serials and exact ISO local date/timestamp text, returning the whole-day serial. Timestamp strings are parsed without local timezone conversion; timezone suffixes and culture-based formats are rejected. `Date.FromText` remains limited to exact ISO dates (`YYYY-MM-DD`).

`DateTime.ToText` writes invariant local ISO timestamp text (`YYYY-MM-DDTHH:mm:ss`) and retains fractional seconds to millisecond precision when present. It does not implement custom format strings, culture options or timezone conversion.

`DateTime.AddDays`, `DateTime.AddHours`, `DateTime.AddMinutes`, and `DateTime.AddSeconds` shift a valid serial or local ISO timestamp by a finite numeric amount while preserving the fractional-day time component. Each offset is limited to 120,000 units and the resulting serial must stay within the worksheet date range. These helpers do not apply daylight-saving or timezone rules.

`DateTime.Date` returns the whole-day serial and `DateTime.Time` returns the fractional-day time component from a valid serial or strict local ISO value. As worksheet serials use binary floating point, the time fraction can have small representation error; compare it with a tolerance where needed.

`DateTime.StartOfDay` returns the date serial at midnight, and `DateTime.EndOfDay` returns the same day at 23:59:59. Calendar offsets include `DateTime.AddWeeks`, `AddMonths`, `AddQuarters`, and `AddYears`; week offsets can be fractional, while month/quarter/year offsets must be whole numbers and clamp to the last valid day in shorter target months. The time fraction is retained. Calendar and datetime bounds still apply, with no timezone or daylight-saving behavior.

Time literals and conversions are available through `#time(hour, minute, second)`, `Time.From`, `Time.FromText`, `Time.ToRecord`, `Time.Hour`, `Time.Minute`, and `Time.Second`. Text parsing requires local `HH:mm:ss` with optional fractional seconds and rejects timezone suffixes. `Time.From` also accepts a numeric fraction in [0, 1); non-empty culture overrides are rejected. Times are worksheet fractional-day numbers, so this subset does not retain a separate native M `time` type.

`Time.StartOfHour` and `Time.EndOfHour` return the beginning and last whole second of the containing hour (`hh:00:00` and `hh:59:59`). They accept the same bounded time fractions or strict local time strings.

`Time.ToText` emits invariant 24-hour `HH:mm:ss` text and includes fractional seconds rounded to milliseconds when present. Custom formats and cultures are not supported.

`Date.AddWeeks` now shifts a date by a bounded whole-number count of seven-day weeks; results outside the worksheet serial range error. Localized date-name formats, datetime zones, calendar/fiscal systems and typed durations remain partial.

`Date.ToRecord` returns Year, Month and Day fields for a valid worksheet date serial or ISO date, so those parts can be flattened with `Table.FromRecords` to build hierarchy columns.

`Table.TransformRows` maps an `each` expression over rows and returns a bounded list of scalar results or flat scalar records. Records can be converted to a worksheet table with `Table.FromRecords`; nested records and lists are rejected.

For a small static lookup, use `#table` and `Table.Join` in one M expression, for example:

```powerquery
let
    Rates = #table({"Region", "Tax"}, {{"East", 0.05}, {"West", 0.08}}),

```

### Local Data Model and DAX subset

Choose **Data → Data Model** to register headered worksheet ranges, add many-to-one relationships, save DAX measures and calculate them. Supported measure expressions include `SUM`, `AVERAGE`, `MEDIAN`, `PRODUCT`, `MIN`, `MAX`, `COUNT`, `COUNTA`, `COUNTBLANK`, `DISTINCTCOUNT`, `DISTINCTCOUNTNOBLANK`, `COUNTROWS`, `VALUES` and `DISTINCT` one-column table inputs, scalar `ADDCOLUMNS`/`SELECTCOLUMNS`, same-table `SUMMARIZE`, `FILTER` (bounded row-filtered table inputs), `SUMX`, `AVERAGEX`, `MEDIANX`, `PRODUCTX`, `MINX`, `MAXX`, `COUNTX`, `COUNTAX`, `RELATED` inside iterators, `DIVIDE`, `IF`, `COALESCE`, `ABS`, `ROUND`, `INT`, `TRUNC`, `ROUNDUP`, `ROUNDDOWN`, `MOD`, `POWER`, `SQRT`, `DATE`, `YEAR`, `MONTH`, `DAY`, `QUARTER`, `WEEKDAY`, `WEEKNUM`, `TOTALYTD`, `TOTALQTD`, `TOTALMTD`, `DATESYTD`, `DATESQTD`, `DATESMTD`, `DATESBETWEEN`, `DATESINPERIOD`, `DATEADD`, `SAMEPERIODLASTYEAR`, `PARALLELPERIOD`, `LEN`, `LEFT`, `RIGHT`, `TRIM`, `UPPER`, `LOWER`, `CONCATENATE`, `CONCATENATEX` (source-order row concatenation with an optional delimiter), bounded numeric `RANKX` with an explicit comparison value, inclusive and exclusive `PERCENTILE.INC`/`PERCENTILEX.INC` and `.EXC` variants, column and iterator `STDEV.P`, `STDEV.S`, `VAR.P`, and `VAR.S` statistical measures, `BLANK`, `ISBLANK`, `HASONEVALUE`, `ISFILTERED`, `SELECTEDVALUE`, arithmetic, text concatenation, Boolean operators, and bounded `CALCULATE` filters. The date helpers accept serial/ISO dates; `WEEKNUM` accepts system 1 return types 1, 2, and 11–17 plus ISO type 21. `TOTALYTD`, `TOTALQTD`, and `TOTALMTD` provide calendar-period accumulation from the latest visible date; fiscal-year end arguments and general DAX time-intelligence tables are unsupported. `DATESYTD`, `DATESQTD`, and `DATESMTD` work as bounded `CALCULATE` filters; `DATESBETWEEN` accepts inclusive ISO/serial endpoints and BLANK() bounds. `DATESINPERIOD` accepts a date column, ISO/serial start, integer interval count, and DAY/MONTH/QUARTER/YEAR unit as a bounded CALCULATE filter. `DATEADD` shifts currently visible date values and matches the shifted values to the model date column, also as a bounded CALCULATE filter; `SAMEPERIODLASTYEAR` shifts the visible values back one year; `PARALLELPERIOD` returns the full shifted month, quarter, or year periods. Virtual DAX tables are capped at 1,000,000 cells. The local model reads worksheet data when a measure is calculated and propagates one-way filters through active one-to-many relationship chains. It is saved in GridForge workbook JSON. XLSX export warns that this GridForge-only model is omitted; the output is not an Excel Power Pivot model. For the supported syntax and remaining limits, see [the local Data Model and DAX subset guide](LOCAL_DATA_MODEL_DAX_SUBSET.md).

In the Windows desktop app, **Data → Authenticated Web Data** can import a bounded CSV or JSON response over HTTPS using no authentication, Basic authentication, or a Bearer token. The credential is used for that request only, cleared from the dialog afterward, and never stored in workbook JSON. Redirects are rejected; the response is limited to 3 MB. This is a one-time import and does not save credentials or a refreshable query definition.

In the Windows desktop app, **Data → SQLite Query** can run one bounded read-only SQL query against a local SQLite file selected through a native file picker and load the results into the active sheet. The file path is held only in a random desktop-session handle and does not go into the workbook. Writes, schema changes, attachments and extension loading are blocked. It is not a refreshable Power Query connection; see [the SQLite connector notes](SQLITE_READONLY_CONNECTOR.md).

In the supported Power Query M subset, List.Product multiplies finite numeric values and List.Median returns a numeric median; both skip nulls and can be used as scalar grouping or pivot reducers. Empty input returns null. Product precision options and nonnumeric/date median behavior are not supported.

List.Percentile supports scalar or list probabilities with Excel inclusive interpolation by default and an explicit PercentileMode.ExcelInc or PercentileMode.ExcelExc options record. Only numeric list inputs and these two Excel-compatible modes are implemented; SQL interpolation modes and general Power Query options records are not supported.

List.Sort orders bounded, homogeneous scalar lists with null values allowed, using Order.Ascending by default or Order.Descending when specified. Text comparisons use the subset's fixed English collation; mixed scalar types and custom comparers are rejected.

The list slicing subset includes List.FirstN, List.LastN, List.Skip, List.RemoveFirstN, List.RemoveLastN, and List.Range, with non-negative whole-number counts/offsets capped at 12,000. Skip/remove calls may omit the count to remove one boundary item. First/last/skip/remove operations also accept an `each` predicate and stop at the first non-match from the relevant end; predicate results must be logical.

`List.StandardDeviation` computes the sample deviation for at least two finite numeric items. Unlike the null-skipping numeric aggregations, this function rejects nulls and nonnumeric items in the current subset. It can be used as a bounded scalar `Table.Pivot` aggregation.

`List.Mode` returns the most frequent finite scalar, selecting the tied mode whose last occurrence appears latest in the input; `List.Modes` returns all tied modes in first-appearance order. Empty lists and nested values fail explicitly, and custom equation criteria are unsupported. `List.Mode` is allowed as a scalar `Table.Pivot` aggregation.

`List.Zip` pads shorter input lists with nulls, `List.Split` emits sequential pages, `List.Repeat` caps total output at 12,000 values, and `List.Positions` returns zero-based offsets. Custom lazy/infinite lists are outside the bounded evaluator.

`Table.MaxN` and `Table.MinN` select up to 1,000 highest/lowest rows using one existing homogeneous scalar column, returning the rows in descending/ascending order with stable tie order. Composite comparison criteria and custom comparers are unsupported; count or boundary-predicate forms are supported.

`List.MaxN` and `List.MinN` return a bounded top or bottom list after scalar sorting. They accept a non-negative count or a logical `each` condition that selects the contiguous sorted prefix; mixed scalar types and custom comparers are unsupported.

`List.Alternate` supports skip counts, an optional keep count, and an initial offset. All parameters are bounded whole numbers; comparer and lazy-list behavior are not implemented.

`List.InsertRange`, `List.RemoveRange`, and `List.ReplaceRange` use bounded zero-based offsets and preserve unaffected items. Range removals/replacements truncate at the source end, and inserted/replacement results remain within the 12,000-item limit.

`List.ReplaceMatchingItems` applies ordered `{old, new}` scalar replacement pairs in sequence, so later pairs can match values inserted by earlier pairs. Work is capped at 12,000 source/replacement comparisons; optional equation criteria and nested values are unsupported.

`List.Single` raises an error unless the list contains exactly one item. `List.SingleOrDefault` returns a supplied default (or null) for an empty list and raises when there are multiple items; it is also available as a scalar `Table.Pivot` aggregator.

`Table.InsertRows` accepts scalar list rows matching the table width or records containing exactly the source columns. The operation validates the insertion offset, row budget, and cell budget before creating the new table.

`Record.ToList` and `Record.FieldValues` return a bounded record's field values in its declared order. `Table.FromList` accepts either function as a record-value splitter; each input list item must be a record whose values fit the explicit output columns. These functions operate on the subset's ordinary record values and do not preserve a table's nested or typed-record metadata.

Record helpers now include `Record.FieldCount`, `Record.FieldNames`, `Record.Field`, `Record.FieldOrDefault`, `Record.HasFields`, `Record.FieldValues`, `Record.ToList`, and `Record.ToTable`. Field lookup uses exact case; missing values can return an explicit default. `Record.ToTable` produces Name/Value columns for bounded scalar fields; `Table.FromList` also accepts `Record.ToList` as a record-values splitter; nested field values and typed-record metadata are unsupported.

Record transformations now include `Record.AddField`, `Record.SelectFields`, `Record.RemoveFields`, `Record.RenameFields`, `Record.ReorderFields`, `Record.TransformFields`, and `Record.Combine`. They keep an explicit field order, reject duplicate output names, and support the documented bounded `MissingField` choices where applicable. `Record.AddField` is eager; a true delayed-evaluation flag is not supported (omit it or pass false/null).

`Table.FromValue` creates a one-column table from one value or a bounded list of scalar values. Its optional options record supports only `DefaultColumnName`; nested values and other table options are rejected.

Table metadata also includes `Table.ColumnCount` and `Table.ApproximateRowCount`. Because GridForge materializes this bounded worksheet M table before evaluation, the latter reports its exact in-memory row count here; it does not estimate an external or streaming source.

`Record.TransformFields` accepts bounded scalar functions or `each` expressions, applies them only to named fields, and follows the selected missing-field policy. Transformations returning nested values are rejected. Record literals also reject repeated field names while preserving case-sensitive fields and declared order.

M equality now compares bounded lists recursively in order and compares records by exact field names and values, independent of field enumeration order. The `&` operator concatenates text or lists, and merges records with right-side values taking precedence while retaining stable field order. Structured nesting is capped at 64 levels; table values are not structurally compared.

`Table.Combine` can optionally receive an explicit column-name list. In that mode it emits the requested schema order, fills missing columns with null, and drops unrequested columns; without the list it still unions headers from the inputs.
