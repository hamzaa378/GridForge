# GridForge local Data Model and DAX subset

GridForge now has a worksheet-backed local model, separate from Excel's Power Pivot/VertiPaq Data Model. Use **Data → Data Model** to register a worksheet range with a header row. Model metadata and measures are stored in GridForge workbook JSON. XLSX export warns that those definitions are not exported as Excel Data Model parts.

## Tables and relationships

- Up to 64 named tables; a table may reference a range on any workbook worksheet.
- Source ranges are limited to 500,000 cells per table and 1,000,000 cells across the whole model; they need nonblank, unique headers.
- Up to 256 many-to-one relationships. Enter `Sales[Customer ID] = Customers[ID]` to make the first key the many-side and the second the one-side.
- One-side keys must be unique (blank keys are ignored). Active relationships filter in one direction, from the one-side table to the many-side table. Filters can propagate through multi-hop one-to-many chains, for example Date → Calendar → Sales.
- Tables are read when a measure is calculated. Source edits therefore appear on the next calculation. The model currently materializes source rows in memory; it does not use VertiPaq compression or query folding. Relationship-based filter propagation stops with a clear message after 8 million row/filter checks in one evaluation, to prevent an oversized model from locking the UI.

## Supported DAX measures

Virtual DAX table results are limited to 1,000,000 cells, matching the total model source limit. The safe expression parser accepts `SUM`, `AVERAGE`, `MEDIAN`, `PRODUCT`, `MIN`, `MAX`, `COUNT`, `COUNTA`, `COUNTBLANK`, `DISTINCTCOUNT`, `DISTINCTCOUNTNOBLANK`, `COUNTROWS`, `VALUES` and `DISTINCT` as bounded one-column table inputs, `ADDCOLUMNS`, `SELECTCOLUMNS`, and same-table `SUMMARIZE` projections, `FILTER` (bounded row-filtered table inputs), `SUMX`, `AVERAGEX`, `MEDIANX`, `PRODUCTX`, `MINX`, `MAXX`, `COUNTX`, `COUNTAX`, `DIVIDE`, `IF`, `AND`, `OR`, `NOT`, `COALESCE`, `ABS`, `ROUND`, `INT`, `TRUNC`, `ROUNDUP`, `ROUNDDOWN`, `MOD`, `POWER`, `SQRT`, `DATE`, `YEAR`, `MONTH`, `DAY`, `QUARTER`, `WEEKDAY`, `WEEKNUM`, `TOTALYTD`, `TOTALQTD`, `TOTALMTD`, `DATESYTD`, `DATESQTD`, `DATESMTD`, `DATESBETWEEN`, `DATESINPERIOD`, `DATEADD`, `SAMEPERIODLASTYEAR`, `PARALLELPERIOD`, `LEN`, `LEFT`, `RIGHT`, `TRIM`, `UPPER`, `LOWER`, `CONCATENATEX` (bounded source-order row concatenation), `CONCATENATE`, `RANKX` (numeric subset), `PERCENTILE.INC`, `PERCENTILEX.INC`, `PERCENTILE.EXC`, `PERCENTILEX.EXC`, column/iterator `STDEV.P`, `STDEV.S`, `STDEVX.P`, `STDEVX.S`, `VAR.P`, `VAR.S`, `VARX.P`, and `VARX.S`, `BLANK`, `ISBLANK`, `HASONEVALUE`, `ISFILTERED`, `SELECTEDVALUE`, arithmetic, text concatenation with `&`, comparisons, Boolean `NOT`, `&&`, and `||` (with short-circuit evaluation and DAX precedence), and `CALCULATE` with equality filters such as `CALCULATE(SUM(Sales[Amount]), Customers[Region] = "West")`. Inside `CALCULATE`, `KEEPFILTERS(Table[Column] = scalar)` intersects the current direct filter; `REMOVEFILTERS(Table[Column])`, `REMOVEFILTERS(Table)`, `ALLEXCEPT(Table, Column, ...)`, and bounded `ALL(...)` aliases clear direct filters. As table inputs to `COUNTROWS` and X iterators, `ALL(Table)` removes direct filters on that table, while `ALL(Column)` removes that column filter and returns distinct visible values. Other general table-valued expressions remain unsupported. Expressions are bounded to 4,000 characters, 2,000 tokens, and 64 parenthesis/unary levels. Model tables use names matching the GridForge identifier rules; column names can include spaces inside brackets. `DIVIDE` returns blank for a zero denominator unless an alternate result is supplied. `COUNTROWS` accepts a model table, `FILTER`, `VALUES(column)`, `DISTINCT(column)`, `ALL(table/column)`, `ADDCOLUMNS`, `SELECTCOLUMNS`, or same-table `SUMMARIZE`; `VALUES`/`DISTINCT` and `ALL(Column)` expose one distinct column; the other table forms return their documented columns. These table values are accepted only in `COUNTROWS`/X-iterator positions. `VALUES`/`DISTINCT`/`ALL(Column)` preserve blank as one distinct value. `COUNTROWS` and `SUM` return blank for empty/no-numeric inputs; `DISTINCTCOUNT` counts a blank value once; `DISTINCTCOUNTNOBLANK` omits blank values. Both return blank for an empty filtered set. `SELECTEDVALUE` accepts an optional alternate scalar and uses the current filter context; `ISFILTERED` checks a direct filter on that column. `FILTER(table, Boolean row expression)` produces a bounded filtered row set when used as the table input to `COUNTROWS` or an X iterator; nested filters are allowed and intersect the existing direct filter context. General table expressions other than the documented `ADDCOLUMNS`, `SELECTCOLUMNS`, same-table `SUMMARIZE`, `FILTER`, `VALUES`, `DISTINCT`, and `ALL` iterator/COUNTROWS inputs, context transition, and measures inside predicates are not implemented. `ADDCOLUMNS` can reference columns from its current table and add up to the parser argument limit; `SELECTCOLUMNS` projects named scalar expressions onto a new one-column-per-pair result table; same-table `SUMMARIZE` groups one to fifteen existing columns under the current filter context; it does not support measures, arbitrary related-table columns, or nested table output. The X iterator functions and `CONCATENATEX` evaluate scalar expressions using columns from the iterated table's current row and `RELATED` on an active many-to-one path; they do not apply context transition or resolve arbitrary other-table columns. `CONCATENATEX(table, expression, delimiter)` accepts an optional scalar delimiter, emits rows in the worksheet-backed source order (no sort/order-by arguments), converts blank values to empty text while retaining their row separators, returns blank for an empty table, and rejects results over 32,767 characters. `RANKX(table, expression, value, order, ties)` requires an explicit numeric comparison value in this subset, ranks numeric/blank row results (blank is treated as zero), accepts ASC/1 or DESC/0 and DENSE/SKIP, and returns blank for an empty table. Text ranking and omitted comparison values are unsupported. `PERCENTILE.INC(column, k)` and `PERCENTILEX.INC(table, expression, k)` ignore nonnumeric results, use inclusive linear interpolation for a numeric `k` from 0 through 1, and return blank for an empty numeric input. `PERCENTILE.EXC(column, k)` and `PERCENTILEX.EXC(table, expression, k)` use exclusive interpolation for 0 < k < 1; combinations whose rank falls outside the available numeric values are rejected, and fewer than two numeric inputs return blank. Measures can be saved and calculated in the Data Model dialog.

The date functions `DATE`, `YEAR`, `MONTH`, `DAY`, `QUARTER`, and `WEEKDAY` are available in scalar and iterator expressions. `DATE` accepts finite numeric year/month/day values, normalizes month and day overflow, follows DAX 0–1899 year adjustment, and emits Excel 1900-system serials including serial 60 for 1900-02-29. `WEEKDAY` accepts return types 1, 2, and 3; `WEEKNUM` supports system 1 start days (return types 1, 2, and 11–17) and ISO 8601 type 21. The bounded scalar functions `TOTALYTD`, `TOTALQTD`, and `TOTALMTD` accept an expression and a date-column reference, find the latest visible serial/ISO date, clear that date table's direct filters, then evaluate through that date from the start of its calendar year/quarter/month. `DATESYTD`, `DATESQTD`, and `DATESMTD` produce bounded date filters only as `CALCULATE` arguments; `DATESBETWEEN` does the same for inclusive ISO/serial bounds, with BLANK() endpoints expanding to the full model date-column minimum or maximum. `DATESINPERIOD(dateColumn, startDate, count, DAY|MONTH|QUARTER|YEAR)` works only as a `CALCULATE` filter, using an inclusive range between the start date and shifted endpoint; month/year shifts clamp to the last valid day of the target month. `DATEADD(dateColumn, count, interval)` shifts the currently visible dates by a bounded integer DAY/MONTH/QUARTER/YEAR offset and matches them back to available date-column rows. `SAMEPERIODLASTYEAR(dateColumn)` is a one-argument convenience that shifts visible dates back one calendar year using the same bounded mapping behavior. `PARALLELPERIOD(dateColumn, count, MONTH|QUARTER|YEAR)` selects complete shifted calendar periods spanning the currently visible date range; the interval is limited to month, quarter, or year. Counts are bounded integers, zero keeps the selected dates, and out-of-range arithmetic is rejected. Multiple date filters intersect, while other `CALCULATE` filters apply after those date ranges. Alternate fiscal-year endings and other DAX time-intelligence table functions are not supported. Date inputs accept Excel 1900-system serials or unambiguous ISO date strings only; locale-formatted date text and full DAX datetime coercion are not supported.

Examples of the supported iterator form are `SUMX(Sales, Sales[Quantity] * Sales[UnitPrice])` and `SUMX(Sales, Sales[Quantity] * RELATED(Products[Price]))`. `RELATED` follows a single unambiguous active many-to-one path and returns blank when the foreign key has no match.

The engine rejects unsupported DAX instead of approximating it. Calculated columns, time-intelligence functions, variables, arbitrary filter expressions, iterators over other tables, context transition and measure references inside iterators, bidirectional or many-to-many relationships, role-playing dimensions, security roles, and Excel PivotTables connected to the model are not implemented. Directed cycles in active relationships are rejected; more complex ambiguous-path rules are not validated to Power Pivot's full behavior. This is not Power Pivot or DAX parity.

## External data and OLAP

No authenticated database connector or OLAP client is included. Existing external refresh remains public HTTPS CSV/JSON, with browser CORS requirements, no credentials, redirects rejected, and a 3 MB response limit. A secure desktop connector service with credential storage, connection allowlists, driver management and cancellation is required before adding database or Analysis Services access.

Statistical aggregation coverage includes sample/population variance and standard deviation over a model column or bounded iterator expression. Blank values are skipped; sample forms require at least two nonblank numeric values, while population forms return blank on empty inputs. Non-numeric values are rejected in these functions in this subset.
